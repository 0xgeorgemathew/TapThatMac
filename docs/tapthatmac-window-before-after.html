Window shell design · before / after · 14 September 2026

One settings window, rebuilt around a sidebar.

The current window puts five segmented tabs under a large custom header. The proposed window drops the header, moves Pause into a toolbar, and navigates with four sidebar areas — ChatGPT, Connection, Tap setup, Activity — over a pinned full-width footer.

Scope: the window shell only.
Navigation structure, layout, sizing and chrome. The command ring, the approval companion panel, sensor detection and the ChatGPT adapter are documented elsewhere and deliberately excluded.

Grounded in Sources/TapThatMac/SetupView.swift, TapThatMacApp.swift, PermissionSetupView.swift, the ChatGPT-mode proposal of 12 September, and an Astra design consult of 14 September 2026.

Nothing is deleted; everything is re-homed.

Five sections fold into four areas. The weak points are Actions and Recordings — “Tap setup” can read as sensitivity-only and “Activity” as history-only — so both get explicit headings and jump links at the top of their pages. If users cannot find them, the fix is a fifth sidebar destination, not hidden disclosures.

First-run routing survives. Today the window switches to the Permissions page when Accessibility or Input Monitoring is missing (SetupView.swift:55). Chrome and sizing decisions.

Header removal and sidebar navigation are separate decisions — that is why the middle view exists. The footer is pinned under both columns so status and “Enable & close” never move between pages.

Window chrome

  • Drop the large header. App icon, title and tagline consume ~90 pt of height on every page. The native title “Tap That Mac Settings” and standard traffic lights replace them.
  • Pause recognition moves to the toolbar's trailing edge as a labeled, persistent toggle. Manual pause stays distinct from “actions paused while Settings is open”.
  • Keep a full-width pinned footer: status and latest acknowledgment left, Enable & close right, with an explicit reason whenever the button is unavailable. The footer grows for long messages instead of truncating them.
  • Keep the button's wording. It clears calibration mode, enables actions and closes the window — more than dismissal (AppModel.swift:117). All current disabled conditions carry over: recording, manual pause, simulated input, sampling below 50 Hz. Ordinary window closing stays different from Enable & close.
  • Build with a two-column NavigationSplitView and native sidebar selection; a custom sidebar only if a demonstrated macOS 14 constraint blocks the layout.

The width math. At 720 pt with a 160 pt sidebar, a 1 pt divider and 2 × 20 pt padding, usable page width is ≈ 519 pt (≈ 539 pt with 140 pt). The graph is 260 pt high, not wide — the fixed control rows are the real width risk. At minimum size, readouts stack, threshold buttons wrap to a second row, and lower controls scroll; the graph keeps its height. No horizontal scrolling, no smaller type. If ~519 pt proves inadequate in a native render, retain segments at 720 pt rather than shrinking content.

What Astra said.

A design consultation on the window shell only, run on 14 September 2026 against this checkout. Read-only; the model inspected the window code, the proposal and the earlier navigation decision before answering.

Recommend a sidebar for the proposed expanded window, conditionally on preserving discoverability and passing the 720 × 640 layout comparison. Keep segmented navigation as the implementation baseline until that comparison succeeds. Five existing sections alone do not justify replacing it.

The conditions that would reverse the sidebar call: essential destinations become difficult to find, minimum-width controls clip, or fitting the sidebar requires shrinking text or the graph. The choice also tracks product scope — sidebar if the expanded ChatGPT experience ships, compact segmented shell if ChatGPT remains one action among several. The earlier review's safeguard (“prototype a sidebar separately at 720 × 640”) still applies; the proposal's HTML wireframe does not prove native minimum-size fit.
