# Development

`Package.swift` is the source of truth. Keep the native SwiftPM layout; no generated Xcode project is required. Use Swift 6 or newer with the existing Swift 5 language mode. Do not change language mode as part of unrelated cleanup.

## Validation

```sh
bash scripts/check.sh
```

This runs the deterministic tests, builds all release executables, and validates shell syntax and bundle property lists. CI uses the same script on macOS. It does not launch the app, request permissions, register a helper, lock the machine or notarize a release.

For a focused edit, run `swift test --filter TapConsistencyTests` (or the relevant test class), then the full checks before committing. Preserve working knock detection when changing light taps. Add a failing regression first for detector/state bugs and verify both intentional taps and negative activity. Counts alone do not establish event identity.

For hardware checks, build a consistently signed bundle, close settings, and exercise repeated ring open/dismiss/open. Save recent activity immediately after a miss. Record rate, threshold, hardware, tap location and intended events. Keep private captures in ignored `diagnostics/` or outside the repository. Promote only reviewed, minimal recordings into `Tests/TapCoreTests/Fixtures` and register new resources in `Package.swift`.

```sh
swift run SensorProbe
swift run ReplayCaptures path/to/export.json --purpose Verification 2
```

SensorProbe reads for five seconds without actions. ReplayCaptures expects complete labeled Calibration or Verification captures; it does not score unlabelled recent-activity exports. It returns nonzero for mismatches or unscored recordings. Keep calibration and verification partitions separate.

## Changes

Use small commits grouped by behavior: `feat(detector): ...`, `fix(ring): ...`, `test(replay): ...`, `chore(build): ...`. Each commit should build independently. Explain the trigger, resulting behavior and checks in pull requests. Do not mix detector tuning with formatting or artwork changes.

Favor explicit state transitions and local changes. Do not add dependencies, migrate to another language, or rewrite working subsystems without evidence. Measure whole-app CPU under matched conditions before claiming performance improvements; detector microbenchmarks exclude UI and sensor delivery.

## Repository boundaries

Commit source, curated regression fixtures, required artwork and build scripts. Keep build outputs, caches, signing keys, personal IDE state, raw captures and local experiment logs out of Git. `dist/` is regenerated by packaging. The installed app and Application Support data live independently of this checkout.

The initial commits import the existing POC by feature; they do not reconstruct historical implementation order. No remote is required for local development. CI starts once this repository is hosted on GitHub.
